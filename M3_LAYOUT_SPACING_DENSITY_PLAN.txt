1. الرؤية الهندسية والأهداف (Architecture Vision)
--------------------------------------------------------------------------------
تحويل لوحة التحكم (Dashboard) من مجرد واجهات متجاوبة تقليدية إلى نظام تصميم هندسي
متكامل (Enterprise Design System) يحقق:

1. صفر أرقام عشوائية (Zero Hardcoded Values):
   استبدال كافة أرقام المسافات والهوامش بـ Design Tokens رسمية متسقة.

2. الكثافة التكيفية للديسكتوب (Compact Density for Desktop):
   مضاعفة كمية البيانات المعروضة في جداول وكروت لوحة التحكم على أجهزة الكمبيوتر
   دون التضحية بمساحات اللمس على الموبايل.

3. التكيف الهيكلي (Adaptive Scaffold & Panes):
   التحول الذكي بين (Bottom Bar <-> Rail <-> Persistent Drawer)، واستخدام لوحات
   المحتوى الثنائية (List-Detail & Supporting Panes).

4. احتواء المساحة والتنفس البصري (Max-Width Containment):
   منع التمدد اللانهائي على الشاشات الكبيرة (Ultra-wide 2K/4K) وضمان راحة العين
   عبر سقف عرض أقصى 1360dp - 1440dp وتوسيط المحتوى بهوامش متماثلة.

5. التوافق التام مع الاتجاهية الثلاثية (Trilingual RTL/LTR):
   محاذاة تلقائية 100% بين العربية (RTL) حيث يبدأ التنقل من اليمين، والإنجليزية
   والهندية (LTR) حيث يبدأ من اليسار.

2. المراحل التنفيذية الخمس (The 5 Execution Phases)
================================================================================

المرحلة 1: بناء محرك الـ Design Tokens للمسافات (Spacing Tokens Engine)
--------------------------------------------------------------------------------
الهدف: إنشاء ملف مركزي يحتوي على كامل سلم الرموز المعتمد من M3، ويُمنع تماماً
كتابة أرقام مثل 8, 16, 24 يدوياً في الكود.

الملف المقترح: lib/core/theme/m3_spacing_tokens.dart

محتوى الكود النموذجي:
--------------------
import 'package:flutter/material.dart';

abstract class M3SpacingTokens {
  // --- السلم الرقمي الأساسي (مبني على مضاعفات 4dp و 8dp) ---
  static const double space0  = 0.0;
  static const double space1  = 4.0;    // محاذاة دقيقة ومسافات الأيقونات
  static const double space2  = 8.0;    // وحدة الأساس للمسافات بين العناصر
  static const double space3  = 12.0;   // حقول الإدخال المضغوطة والـ Pills
  static const double space4  = 16.0;   // حشو الكروت والقوائم القياسي
  static const double space5  = 20.0;   // فواصل الأقسام المتوسطة
  static const double space6  = 24.0;   // حشو الـ Dialogs والفواصل بين الأعمدة
  static const double space7  = 28.0;   // رؤوس الأقسام البارزة
  static const double space8  = 32.0;   // فواصل المجموعات الكبيرة
  static const double space10 = 40.0;   // فواصل أقسام الـ Hero
  static const double space12 = 48.0;   // هوامش الصفحات وأدنى مساحة لمس
  static const double space16 = 64.0;   // هوامش الشاشات العريضة جداً

  // --- الرموز الدلالية الوظيفية (Semantic Tokens) ---
  static const double inlineIconGap       = space1; // 4dp بين الأيقونة والنص
  static const double siblingGap          = space2; // 8dp بين العناصر المتجاورة
  static const double cardInternalPadding = space4; // 16dp داخل الكروت
  static const double sectionVerticalGap  = space6; // 24dp بين أقسام الداشبورد
  static const double minTouchTarget      = space12; // 48dp أدنى مساحة لمس

  // --- الحشو الاتجاهي التلقائي (RTL / LTR) ---
  static const EdgeInsetsDirectional pagePaddingCompact = 
      EdgeInsetsDirectional.all(space4);
  static const EdgeInsetsDirectional pagePaddingExpanded = 
      EdgeInsetsDirectional.symmetric(horizontal: space6, vertical: space4);
}


المرحلة 2: تطبيق نظام الكثافة التكيفي (Adaptive Density System)
--------------------------------------------------------------------------------
الهدف: التمييز بين نمط الماوس عالي البيانات (Desktop) ونمط اللمس المريح (Mobile).

المعايير المعتمدة:
1. على أجهزة الديسكتوب (Expanded >= 840dp):
   - تفعيل VisualDensity.compact للجداول.
   - ارتفاع صفوف الجدول (Table Row Height) ينخفض من 56dp إلى 40dp.
   - حشو الخلايا (Cell Padding) يصبح 8dp أفقي و 6dp رأسي.
   - حقول الإدخال ينخفض ارتفاعها إلى 40dp.

2. على أجهزة الموبايل (Compact < 600dp):
   - استخدام الكثافة الافتراضية (VisualDensity.standard).
   - ارتفاع الصفوف 52dp - 56dp.
   - ضمان مساحة لمس للأزرار لا تقل عن 48dp x 48dp (باستخدام invisible padding).

3. قاعدة الكثافة الموحدة:
   - يمنع خلط مستويات كثافة مختلفة داخل نفس القسم لتجنب الإيقاع البصري المكسور.


المرحلة 3: تفعيل شبكة الأعمدة واحتواء الشاشة (Grid & Containment)
--------------------------------------------------------------------------------
الهدف: منع تشوه الكروت الإحصائية والجداول على الشاشات الكبيرة (2K / 4K).

المعايير المعتمدة:
1. توزيع الأعمدة لكروت المؤشرات (KPI Cards):
   - Compact (< 600dp): عمود واحد (1 Column).
   - Medium (600 - 839dp): عمودان (2 Columns).
   - Expanded (840 - 1199dp): 3 أو 4 أعمدة.
   - Large+ (>= 1200dp): 4 أعمدة متساوية بفواصل (Gutters) ثابتة 24dp.

2. سقف العرض الأقصى (Max-Width Containment):
   - إحاطة جميع واجهات الداشبورد بـ M3ContentBoundary:
     * سقف الداشبورد العام: maxWidth = 1360dp.
     * سقف شاشات الجداول الكثيفة (سجل الفواتير): maxWidth = 1440dp.
   - توسيط المحتوى أفقياً (Alignment.topCenter) مع هوامش متماثلة على الأطراف.


المرحلة 4: هيكلة الشاشات بنظام الألواح المعتمد (Canonical Panes Architecture)
--------------------------------------------------------------------------------
الهدف: التخلص من التنقل بين صفحات كاملة على الديسكتوب، واستغلال الشاشة بعرض
لوحات متزامنة.

خريطة توزيع الشاشات:
1. شاشة سجل الفواتير (InvoicesLogScreen):
   - النمط: List-Detail Layout (M3ListDetailLayout).
   - ديسكتوب: قائمة الفواتير على اليمين بعرض ثابت 360dp، وتفاصيل الفاتورة
     المحددة وصورتها ومعالجة الـ OCR على اليسار مباشرة وبشكل فوري (0ms).
   - موبايل: القائمة تملأ الشاشة، والنقر ينقل لصفحة تفاصيل مستقلة.

2. لوحة تحكم المدير (CompanyManagerPortalScreen):
   - النمط: Supporting Pane Layout (M3SupportingPaneLayout).
   - ديسكتوب: الإحصائيات والجداول في اللوح الرئيسي، ولوح جانبي (320dp) للفلاتر
     السريعة والإشعارات.
   - موبايل: اللوح الجانبي يفتح كـ Modal Bottom Sheet عند النقر على زر الفلاتر.

3. شبكة كروت الهدايا والجوائز:
   - النمط: Feed Layout (M3FeedLayout) تتراصف في 4 أعمدة على الشاشات الواسعة.


المرحلة 5: معايير الاتجاهية وحوكمة الـ RTL (Trilingual Directionality)
--------------------------------------------------------------------------------
1. محاذاة القوائم (Start Alignment):
   - في العربية (RTL): شريط التنقل (Rail / Drawer) يكون على اليمين.
   - في الإنجليزية والهندية (LTR): شريط التنقل يكون على اليسار.
   - يتم ذلك بجعل الـ Rail/Drawer أول عنصر في Row(children: [rail, expandedBody]).

2. الحشو والفواصل الاتجاهية:
   - ممنوع استخدام EdgeInsets.only(left/right).
   - الإلزام الصارم بـ EdgeInsetsDirectional.only(start/end).
   - استخدام BorderDirectional(end: BorderSide(...)) للفواصل الرأسية.

4. مصفوفة التحقق والقبول (Acceptance Criteria)
================================================================================

1. Spatial Scale:
   جميع المسافات والـ padding مضاعفات لـ 4dp/8dp ولا توجد أرقام عشوائية في الكود.

2. Desktop Density:
   جداول الديسكتوب تعرض صفوفاً بارتفاع 40dp، وتتسع لـ 9+ صفوف في نفس المساحة الرأسية.

3. Touch Safety:
   جميع أزرار الهاتف والأيقونات تحقق مساحة لمس 48x48dp على الأقل.

4. Multi-Pane Experience:
   شاشة الفواتير تعرض القائمة والتفاصيل جنباً إلى جنب على شاشات >= 840dp في 0ms.

5. Max-Width Breathing:
   عند تكبير الشاشة إلى 2560px (4K/2K)، لا يتمدد المحتوى بشكل عشوائي، بل يتوسط الشاشة
   بهوامش متماثلة ومريحة للعين.

6. RTL / LTR Mirroring:
   في الواجهة العربية، القوائم الجانبية تبدأ من اليمين، والـ start padding يبدأ من اليمين.
